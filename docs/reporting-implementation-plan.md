# Reporting System Detailed Implementation Plan

Date: 2026-02-05
Owner: Super Admin
Status: Draft

## Confirmed Requirements
- Each module has a separate report format based on its data.
- Reports flow: Generate -> Review -> Push -> Centralized MD view.
- HR reports visible to Super Admins and HR Admins.
- Reports are auto-generated by the system with a protected data layer.
- Users can add text annotations without modifying system-generated data.

## Objectives
- Build a centralized Reporting module with standardized lifecycle controls.
- Embed report generation inside each module to keep data close to source.
- Ensure report integrity to prevent tampering, forgery, or theft.
- Support auto-generation plus safe human annotations.
- Provide export and distribution tooling for leadership.

## Scope
Modules in scope:
- Production
- Sales
- Inventory
- Accounting
- HR

Central Reporting:
- Dashboard
- Generate Reports
- Review Reports
- Compile Reports
- Send to Managing Director

## Roles and Permissions
Role: Super Admin
- Access: All modules, all reports, all actions.
- Can Send to Managing Director.
- Can view HR reports.

Role: Department Admin
- Access: Reports for their department only.
- Can Generate, Review, Push department reports.
- Cannot Send to Managing Director.

Role: HR Admin
- Access: HR reports only.
- Can Generate, Review, Push HR reports.
- Cannot Send to Managing Director unless also Super Admin.

Role: Managing Director (MD)
- Access: Centralized compiled reports only.
- Read-only.

## Report Lifecycle
1. Generate (module)
2. Review (module)
3. Push (module -> central)
4. Compile (central)
5. Send to MD (central, Super Admin only)

State transitions:
- Draft -> In Review -> Approved -> Pushed -> Compiled -> Sent
- Rejected returns to Draft with reviewer feedback.

## Data Integrity and Anti-Tamper Design
- System Data Block: immutable, auto-generated.
- Annotation Block: user-added text, separate storage.
- Combined View: rendered as a single report output, but stored separately.

Integrity controls:
- Report hash for system data block.
- Audit trail for each state transition.
- Immutable system data after generation.
- User annotations are versioned and attributable.

## Data Model (High-Level)
Entities:
- Report
  - id, module, period, status, created_by, created_at
  - system_data_hash, system_data_version
  - review_status, reviewer_id, reviewed_at, review_notes
  - pushed_at, compiled_at, sent_at

- ReportSystemData
  - report_id (FK)
  - payload (structured JSON)
  - generated_at
  - generator_version

- ReportAnnotation
  - id, report_id (FK)
  - author_id
  - body (text)
  - created_at, updated_at

- ReportAuditLog
  - id, report_id (FK)
  - action, actor_id, timestamp
  - metadata (JSON)

## Module-Specific Report Engines
Each module implements:
- Report templates and KPIs for that module.
- Report generation API (internal).
- Validation of required data before generation.

Module output standard:
- JSON payload schema with:
  - summary metrics
  - detail tables
  - timestamps and sources
  - generator version

## Central Reporting Module
### Dashboard
- Overview of latest reports by module.
- Status counts and pending reviews.
- Latest sent reports and MD delivery history.

### Generate Reports (Central)
- Trigger module report generation (admin-only control).
- Show report templates by module.

### Review Reports
- View generated report with system data and annotations.
- Approve or reject with comments.

### Compile Reports
- Combine multiple module reports into consolidated MD report.
- Include module summaries and top-level KPIs.

### Send to MD
- Super Admin only.
- Send compiled report to MD view.
- Record delivery in audit trail.

## UI/UX Flows
### Module Flow
- Module -> Reports -> Generate -> Review -> Push

### Central Flow
- Reporting -> Dashboard -> Review -> Compile -> Send

### Annotation Flow
- View Report -> Add Notes -> Save
- Notes are displayed in output but stored separately.

## Export and Delivery
Formats:
- PDF
- Excel
- CSV

Delivery:
- MD sees centralized compiled report.
- Optional email dispatch with attached PDF.
- Logs retain delivery metadata.

Module:
- POST /api/{module}/reports/generate

- POST /api/{module}/reports/{id}/push

Central:
- GET /api/reporting/dashboard
- GET /api/reporting/reports
- POST /api/reporting/compile
- POST /api/reporting/send

Annotations:
- POST /api/reports/{id}/annotations
- GET /api/reports/{id}/annotations

## Security Considerations
- Role-based access control on all endpoints.
- Audit log for all transitions.
- Hashing for system data block to detect tampering.
- Separate storage for annotations.
- Read-only access for MD.
